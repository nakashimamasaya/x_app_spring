# 0001. BFF を採用しない

- ステータス: 採用
- 日付: 2026-07-28

## 背景

React SPA と Spring Boot API の間に BFF（Backend for Frontend）を置くかどうか。
BFF があれば、トークンをサーバー側の Cookie セッションに隠せて CORS も不要になる。

## 決定

BFF を置かず、ブラウザから API を直接呼ぶ。

## 理由

このプロジェクトの目的は Spring Boot の REST API と React の学習であり、
BFF を挟むと「API 設計の良し悪し」がフロントから見えにくくなる。
API がブラウザに直接晒される構成の方が、認証・CORS・エラー設計の判断が必要になり学習効果が高い。

構成要素が 1 つ減ることで、Docker Compose とデバッグも単純になる。

## 結果

**得たもの**: 構成が単純。API の設計が SPA からそのまま見える。

**引き受けた責務**: 以下は BFF があれば不要だったが、この構成では必須になる。

- CORS を `SecurityFilterChain` で明示設定する（`allowCredentials=true` が必要）
- Access Token を**メモリ保持のみ**にする（localStorage は XSS で盗まれる）
- Refresh Token を HttpOnly Cookie にし、`Path=/api/v1/auth` に限定する
- 認証系エンドポイントにレート制限を掛ける（ブラウザから直接叩けるため）
- レスポンス DTO に機密を含めない設計を徹底する（[0004](./0004-email-をレスポンスに含めない.md)）

これらを守らないと、BFF 無し構成は素直に脆弱になる。

## 見直す条件

- サードパーティ API の秘密鍵をサーバー側で保持する必要が出たとき
- 複数クライアント（モバイル等）が増え、クライアント固有の集約が必要になったとき
